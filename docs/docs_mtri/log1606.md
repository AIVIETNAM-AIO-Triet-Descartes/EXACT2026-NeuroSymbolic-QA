## Kết quả chạy thử (demo_type2 --limit 100)

### Bug phát hiện sau P0: `_solve_multi_step` alias fallback sai
**Triệu chứng:** Accuracy giảm từ 83.6% → 47.8%. 27 câu E_field electrostatics WRONG(100%).

**Root cause:** P0 thêm alias fallback vào `_solve_multi_step` (lines 192-216) có 2 bug:
1. `for var, val in accumulated.items()` inner loop → `val` leak vào scope ngoài = last given value (0.08)
2. `return {"answer": f"{val:.6g}"}` chạy **unconditionally** khi alias KHÔNG tìm thấy trong accumulated → return garbage `val` thay vì `None`

**Hệ quả:** Scalar solver trả về `E_field = 0.08` (giá trị của `d_perp`) thay vì `None` → vector_solver KHÔNG được gọi (chỉ fallback khi source=llm_fallback).

**Fix:** Đổi `return {...}` bên ngoài `if` thành chỉ return khi `sym_name in accumulated`. Rename `val` → `alias_val` trong alias block để tránh name confusion.

### Kết quả sau fix

| Mode | CORRECT | WRONG | FALLBACK | SKIP | Accuracy |
|------|---------|-------|----------|------|----------|
| No LLM | 46 | 8 | 44 | 2 | **85.2%** (46/54) |
| --use-llm | 46 | 8 | 44 | 2 | **85.2%** (46/54) |

LLM không kết nối (vLLM server offline) → cả hai mode giống nhau. Accuracy **85.2%** > baseline pre-P0 **83.6%** (46/55) — P0 formulas mới (formula_054-060) đang contribute.

**Distribution:**
- 37 FALLBACK electrostatics = multi-charge vector E_field problems chưa có scalar path
- 14 CORRECT E_field electrostatics = P0 symbol normalization (E→E_field) hoạt động đúng
